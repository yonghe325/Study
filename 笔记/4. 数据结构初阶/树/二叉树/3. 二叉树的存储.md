# 顺序存储
即采用数组的方式模拟二叉树,
采用二叉树的索引规则存放数据
==顺序存储最适合用来存储形态接近完全二叉树的树==
保证空间浪费不会太多
## 完全二叉树 
完全二叉树最适合顺序存储
对完全二叉树从上到下,从左到右,从1开始,依次编号
+ ==左分支 : 2i==	
+ ==右分支 : 2i + 1 ==
+ ==父节点 ==: $\lfloor\frac{i}{2}\rfloor$

并将对应编号放入数组中
+ 下标0的地方不放元素
## 二叉树
对于普通二叉树
有些结点不存在
可以将其视为虚拟结点,将其视为完全二叉树
放入对应的下标中,称为==占位==
![[Pasted image 20251204121757.png]]
可以将空位置设为特殊值
特殊值不能与存储元素的值相同
### 最坏情况
当树为右单支树,情况成为最坏
![[Pasted image 20251204122031.png]]
+ 一共需要$2^{h-1}$个结点
	浪费的空间以指数上升(指数爆炸)
+ 实际只利用了h个结点


# 链式存储
==以指针链接所有结点==
```
每个结点由
*left data *right
构成
typedef struct BTNode{
	int data;   //数据域
	struct BTNode* left;   //左分支
	struct BTNode* right;  //右分支
}BTNode;
//BT即Binary Tree(二叉树)的简写
//
```
==所有叶结点多指向NULL==
又该种方式链接所有结点
形成的树又称==二叉链表==
## 优缺点
### 优点
适合所有树,不会浪费空间
### 缺点
 找父节点很麻烦
 因此为每个结点额外添加一个父指针
 ```
 typedef struct BTNode{
	 int data;
	 struct BTNode* left;
	 struct BTNode* right;
	 struct BTNode* parent;//指向父节点
 }BTNode;
 ```
 ==包含父结点的二叉链表称为三叉链表==
## 特殊结论
+ $空指针个数(NULL) = 结点数 + 1$
	假设树共有 n 个结点,则共有 2n 个指针
	其中只有 n-1 个指针指向了有效结点
	所以二叉树中
	一定有$2n-(n-1) = n+1$个==NULL==
